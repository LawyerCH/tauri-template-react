# 质量审查

依据 `docs/quality.md` 的五轴。审查对象是本次改动，不是整个仓库。

## 步骤

### 1. 圈定范围

`git status` + `git diff` 看改了什么。只审本次改动涉及的文件与其直接依赖。

### 2. 五轴过一遍

| 轴 | 必查 |
|---|---|
| 正确性 | 空/单/多条边界；异步失败分支；重复点击；`any`、非空断言、吞掉的 catch |
| 契约 | 字段名与可空性；Rust 命令与 TS 调用是否同步；settings 新字段有默认值与非法值兜底 |
| 可访问性 | 键盘走完全流程；焦点环可见；图标按钮有 `aria-label`；对比度 ≥ 4.5:1 |
| 性能 | 无谓重渲染；依赖数组；构建产物体积异常 |
| 安全 | 无密钥/`.env`；外部输入在边界校验；权限最小化 |

### 3. 实际验证

能跑就跑：

```bash
pnpm check          # 必跑
pnpm check:rust     # 涉及 Rust 时
```

UI 改动用浏览器打开对应路由，看浅色、深色、窄屏各一眼。不要凭读代码下结论。

### 4. 分级输出

```
阻塞（必须改）
- <问题> — <文件:行> — <为什么错> — <怎么改>

建议（可后续）
- ...

通过
- 正确性 / 契约 / 可访问性 / 性能 / 安全：已检查，无阻塞项
```

## 判定标准

**阻塞**：错误行为、数据丢失、安全问题、违反 `AGENTS.md` 铁律、`pnpm check` 失败。
**建议**：可读性、命名、可简化处、测试缺口。
**不算问题**：个人审美、与本次改动无关的历史代码。

## 禁止

- 把风格偏好写成阻塞项
- 没跑命令就说"检查通过"
- 提"整体重写"类建议，除非现状无法局部修复
- 一次报 20 条小问题淹没重点；先报阻塞，再报 3 条以内高价值建议
