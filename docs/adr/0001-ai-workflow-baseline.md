# ADR 0001：模板的 AI 协作基线

- 状态：已采纳
- 日期：2026-10-22

## 背景

模板要支持"AI 全流程开发"，但规则一多 AI 就会陷入流程本身，规则一少又会到处漂移。
需要在两者之间选一组最小、可验证、可扩展的约定。

## 决策

1. **`AGENTS.md` 作为唯一入口**，其他工具文件软链过来。理由：AGENTS.md 已是跨工具事实标准，避免多份规则漂移。
2. **规范分层**：`AGENTS.md` 只放铁律与路由，细节拆到 `docs/*.md` 按需加载。理由：一次性塞满规则会稀释注意力。
3. **项目技能只做薄层**，复用全局技能（`spec-driven-development`、`design-taste-frontend`、`systematic-debugging`），不重复造。理由：技能越多触发越乱。
4. **不引入 Spec Kit 工具链**，只借它的"先规格后实现"阶段模型，产物是普通 Markdown。理由：模板不该为了流程再装一套 CLI。
5. **UI 用 Tailwind + 自有令牌，不用组件库**。理由：模板需要更薄的依赖面与统一的公文风，组件库会带默认审美。
6. **主题用唯一 `data-theme` 属性**。理由：主题来源只能有一处，避免 class 与 media query 双轨。

## 后果

- 好处：规则可枚举、可检查；新项目删示例页即可用；换 AI 工具不用重写规范。
- 代价：文档需要与代码同步维护；`docs/ui.md` 与全局设计规则有少量重复（为了保证项目内自洽）。
- 触发复审的条件：项目规模超过 3 个业务域，或开始接多窗口/多端。
